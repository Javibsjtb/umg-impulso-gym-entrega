# Qué falta para una entrega final defendible

La parte de software está preparada para demostración local. El proyecto académico completo todavía exige:

1. **Negocio real:** identificar gimnasio, obtener autorización, observar el proceso y completar la necesidad con evidencia real.
2. **PRD del curso:** obtener la plantilla del docente, trasladar este borrador y validar reglas con el gimnasio. El prototipo no equivale a un PRD aprobado previamente.
3. **Cinco integrantes:** completar nombres/carnés/usuarios, acordar responsabilidades y asegurar dominio técnico de todos.
4. **Trabajo colaborativo real:** invitar a los compañeros al repositorio y tablero ya creados; cada miembro debe adaptar y mejorar el prototipo con commits, ramas, revisión y PR propios. No fabricar participación.
5. **PostgreSQL:** las 54 pruebas ya pasaron en [CI](https://github.com/Javibsjtb/umg-impulso-gym/actions/runs/38933107025); falta verificar la configuración concreta del proveedor y respaldos.
6. **Publicación:** conectar GitHub con Render/Railway, revisar costos, configurar variables y base persistente, desplegar y verificar una URL HTTPS desde un dispositivo externo.
7. **Operación:** ejecutar restauración de un backup, prueba de carga y aceptación del gimnasio; registrar incidencias reales.
8. **Exposición:** ensayar los cinco, mostrar evidencias, declarar el uso de IA y explicar decisiones.

No hay negocio identificado, entrevistas realizadas, firmas, aprobaciones, reuniones de equipo ni publicación web acreditados en esta entrega. Sí existen repositorio remoto, tablero y PR técnico inicial con autoría IA explícita. Las capturas son del prototipo con datos ficticios.
